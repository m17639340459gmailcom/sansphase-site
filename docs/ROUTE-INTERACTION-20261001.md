# 2026-10-01 切页后按钮短时无响应修复

状态：仅本地完成，未部署、未推送。与作者编辑器、首页顶栏横线修复一起等待发布验收。

## 复现与原因

在生产网站独立 Chromium 中，从博客点击作品，再过约 150ms 点击资源中心。第二次 pointerdown/click 的目标均是 HTML 根节点，路由仍停在作品；等转场结束后，同一坐标才能打开资源中心。本轮该复现区间未记录到 Long Task，明确证据指向快照层拦截，而不是已确认的服务器响应慢。

旧模块使用 document.startViewTransition 捕获整个页面及顶栏，转场期间可见的是快照。内容最多等待 220ms；内页滑入为 600ms 加 50ms 延迟，首页进入为 850ms，能形成接近一秒的不可点击窗口。对快照伪元素仅设置 pointer-events:none 的独立浏览器实验仍命中 HTML，未采用该无效覆盖补丁。

浏览器语义参考：[Chrome 同文档转场说明](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)、[MDN ViewTransition](https://developer.mozilla.org/en-US/docs/Web/API/ViewTransition)。实际本站结论以点击命中记录为依据。

## 最终调整

- 将转场职责迁入 `src/route-transition.ts`，沿用既有构建机制生成稳定 `.mjs` 路径；源目录 `.mjs` 仅保留既有标准的 Node 测试适配入口。
- 路由立即调用现有渲染器，不等待截图或动画；异步内容读取及过期响应保护继续由原模块负责。
- 只对真实 main 内容做轻量透明度过渡（内页 180ms、首页进入 260ms），不移动或裁剪按钮命中区域。顶栏不参与动画。
- 点击、键盘或滚动会停止淡入，输入不被 preventDefault 或重新派发。快速导航取消旧动画；旧动画结束不能清除新动画状态。
- 删除旧快照 CSS、相关关键帧、方向变量与 220ms 等待，移除重复的 enterPage 位移动画、导入和已失去用途的 silent 标志。
- 首页场景自身的出场与返回、导航高亮滑块保持原有逻辑。页面切换的观感由原来全屏滑动/圆形展开改为轻量淡入，这是本次有意的交互调整。

未调整数据库、权限、持久数据、接口、音乐或黑洞渲染代码。

1. 修改前新增浏览器命中回归：首页进入、内页切换、资源中心的导航与正文按钮共六次命中均为 HTML，用例失败；修复后六次均命中目标按钮并收到点击。
2. 新模块单元用例覆盖同步绑定、未完成网络请求、快速切页与旧动画完成竞争、输入中断、减少动态效果、隐藏页面、不支持动画及释放。
3. `pnpm build`（含类型与构建校验）通过。启用 UI 和 GPU Chromium 环境变量后 `pnpm test`：387/387 通过，无跳过。
4. 无数据库的完整本地夹具：1440px 桌面与 390px 手机尺寸，博客→作品→资源中心连续导航，资源中心列表/网格按钮第一次点击生效，无页面异常。
5. 首页真实场景进入作品后约 50ms，资源中心导航坐标可命中链接并切页成功；首页出场流程正常。
6. 证据保存在本地 `outputs/route-interaction-20261001/`，全套测试日志为 `outputs/route-interaction-20261001-tests.log`。

验证范围是 Chromium 与模拟手机尺寸；不等同于全部真实手机或 Safari 验收。修复的是转场拦截输入，不代表网络、重图片或所有长任务已经消除。生产尚未更新。
