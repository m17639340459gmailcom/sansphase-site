# 社区资料与审核

社区“我的主页 → 编辑资料”在当前主页上打开弹窗，不跳转到主站或独立编辑页。旧书签 `#/community/profile` 仍兼容为个人主页上的同一弹窗。头像、个性签名及已有账号的改名使用主站读者账号和既有审核工作流，香港不另建账号或资料副本；审核通过后，主站和社区读取同一份资料。注册昵称仍沿用原注册校验，不重新审核注册流程；改名不增加昵称唯一约束。此弹窗不修改邮箱、手机号、VIP 或经验。

弹窗沿用 `a11y-dialog` 处理键盘聚焦、Escape 和关闭后返回按钮；选图只在本地预览，提交前不上传。未提交的内容在关闭或离开时提醒，进行中的资料提交禁止关闭和从弹窗跳走，失败保留草稿和文件供重试。弹窗关闭、离开页面或切换账号时清理本地预览和背景锁，旧编辑面板与对应布局样式不再使用。

## 权限

| 操作 | 普通读者 | 协管、版主、总版主 | 站长 |
| --- | --- | --- | --- |
| 编辑本人头像、个签、头像框、社区背景 | 可以 | 以真实读者资料操作 | 切换到个人读者身份后可以 |
| 查看待审头像、昵称、个签、背景 | 仅本人 | 仅获授建议或最终审批权限的种类 | 可以 |
| 提交审核建议 | 不可以 | 需要对应种类的建议权限 | 可以 |
| 最终通过或驳回 | 不可以 | 需要对应种类的最终审批权限 | 可以 |

任命沿站长→总版主→版主→协管逐级进行；任命者只能授出自己可继续授予的权限。资料属于账号，头像、昵称、个签、背景的审核权限是逐类授予的全局账号权限，不因用户发过某个板块的帖子自动取得。只有职位名称不能获得审核权限。上级停用、撤职或回收授权会使下级对应权限失效；主站提交前重新核对香港真实任命和主站当前账号状态，不信任浏览器传来的职位或权限。

审核建议与最终审批分开。建议不公开资料、不消费申请；同一操作者可更新自己的建议，保存实际操作者、结论、理由和时间。最终审批依据当前申请，申请更换后旧建议失效。建议驳回和最终驳回都必须说明理由，最多200个可见码点，不接受控制字符和尖括号。批准理由可空；主站及社区使用同一规则。

站长使用同一个作者登录会话，可切换管理身份和真实的个人读者身份。个人身份的头像、个签、昵称和头像框使用独立读者资料，主站和社区互通，不修改 `site_profile` 中的博客作者介绍。社区背景仅用于社区。个人身份可以发帖、回复、签到和编辑资料，不能审核或管理；切回管理身份后恢复站长权限。版主原有的读者浏览视角仍为只读，不影响其现有审核权限。

管理审核权限由当前任命、上级授权、真实账号状态和会话验证，前端按钮不是授权依据。主站私有资料桥只接受有签名、时效和防重放校验的固定命令，用户不能提交其他账号 ID 代改资料。站长个人资料操作通过明确的 `asReader: true` 命令选择私有绑定的读者，管理命令不能携带这个字段；保存和审核在命令队列内重新验证有效会话与身份。任何读者模式都不能执行管理命令。

## 站长双身份配置

主站私有配置中的 `ownerReaderId` 关联一个已验证、未停用的真实 `readers` 实体。配置项必须是明确的 UUID；启动和请求不会自动创建、猜测或重绑读者。香港会话始终绑定原有作者登录，个人操作使用主站签名下发的关联身份；仅修改浏览 cookie 不能获得站长权限或选择其它读者。

首次关联前备份并验证异地副本、在隔离恢复目录运行 `PAYLOAD_CONFIG_FILE=<绝对私有配置路径> node scripts/prepare-owner-reader.mjs --apply --nickname=<2至8字个人昵称>`。在当前发布目录执行时默认公开根目录为 `dist`，其它位置须传 `--public-root=<绝对公开根目录>`。工具沿用 Payload 读者集合及 UID 分配，创建独立资料，不复制博客头像、个签、手机号、VIP 期限或余额。已有关联时只检查，不重置资料；同邮箱实体已存在但未绑定时停止，须核对后明确设置关联。数据库创建成功但配置写入失败时保留该实体，按错误中给出的固定 ID 核对恢复，禁止重复创建。

专属个人身份生命周期随站长账号，不参与普通读者的半年闲置自动清理。普通读者清理规则不变。若绑定缺失或读者停用，个人操作拒绝执行，但仍能切回管理身份；解除绑定或永久清理按持久数据维护流程执行。

个人身份保留已认可的满级、VIP 和全亮徽章展示，其他读者看到相同效果；此展示不写入星尘流水、经验账本、库存或历史成就。实际发帖、签到和兑换仍以专属读者的真实记录计算，余额不足不能借用管理身份余额。编辑草稿按实际角色与 UID 隔离，进行中或结果不确定的写入未处理完时拒绝切换，避免重复扣款或串用草稿。

## 图片与待审资料

头像与背景只接受 JPG、PNG、WebP。本地选图最多 25MiB，可在同一资料弹窗中拖动、缩放与调整裁剪范围；不要求原图为 64×64。头像裁剪为正方形，背景可自由调整比例，裁剪使用 Cropper.js，按需加载而不阻塞社区首页。确认裁剪后才可提交，上传的是重新编码且不超过 2MiB 的 WebP；原始大图不上传。

服务端仍独立验证文件、解码后像素与格式，头像重新编码为 320×320 WebP，背景按最长边不超过 2048 像素重新编码。上传文件通过现有流式工具处理并移除，不接收任意外站图片地址。裁剪失败保留编辑器可重试；关闭、换图或切换身份释放本地资源，过期裁剪结果不能写入新身份。

待审头像、背景只供本人、站长和获得该种类建议或最终审批权限的现任管理人员查看。其它成员只读已通过的头像、昵称、签名和背景；待审昵称通过 `pendingNickname` 单独提示，批准前不覆盖公开名字。私有预览响应禁止缓存，未经审核的图片地址也不能绕过权限直接读取。新提交替换旧申请；审核必须针对当前申请，过期或重复决定拒绝执行。所有驳回必须填写理由。

背景只用于社区个人主页，不同步为主站背景。`community_profile_backgrounds` 每个读者只保存一张已通过图片和一张待审替换图；图片登记仍位于 `community_images`，用途为 `profile`。重复上传替换待审图，审核通过替换当前图，驳回继续使用当前图，不提供个人背景历史库。失去引用的个人背景在事务中加入既有持久文件删除队列；提交后回收，失败重试，删除前再检查商品、横幅、帖子和所有读者当前/待审引用，事务回滚或共享引用不能导致误删。

作者在“社区管理 → 兑换物品 → 上架新物品”选择“主页背景”，沿用商品图片上传、兑换条件和上下架流程。背景是已有装扮种类 `cover`，不建立第二套库存。读者兑换后自动使用，也可在“兑换所 → 已拥有”中使用或恢复默认；下架后已获得的使用权保留，未拥有的引用由服务端拒绝。已兑换的背景商品不能替换其原图。

作者上架背景直接使用，不重复走用户上传审核。商品图片集中保存，读者仅记录当前商品引用，不为每个读者复制图片。使用已拥有背景会取消个人自定义背景及待审申请；个人上传的新背景审核通过后取消当前商品选择，确保主页只显示一个背景。恢复默认取消当前选择和待审图，已拥有的商品权益保留。

## 头像框

社区头像框在“兑换所 → 已拥有”内佩戴或卸下，弹窗只提供入口，不再提供重复的头像框选择表单。库存卡片明确显示“已佩戴 / 佩戴 / 卸下”，仍使用既有 `shop/equip` 接口验证拥有权限，不改变库存和价格。

已拥有和穿戴状态仍以香港社区的 `community_owned`、`community_members.frame` 为准，主站不复制库存。主站资料页显示同一头像框，并在现有头像设置区域选择已拥有的框。自定义框图片由主站受限代理提供，只供验证过拥有权限的本人读取，保留动画。

主站认证不依赖远程头像框查询。展示查询短时缓存并合并并发请求，社区暂不可用时不影响主站登录；打开头像设置才读取完整库存，成功穿戴后刷新展示状态。

## 发布与回滚

先使用完整备份工具备份香港旧数据，下载并验证异地副本、隔离恢复；再显式执行 `node scripts/migrate-community.mjs <private-payload-directory>`。迁移新增背景记录、扩展图片用途约束，并允许商品装扮类型 `cover`，保留原有图片、引用、订单及持有记录。启动不会自动迁移社区表。

主站已有 `reader-workflow.db` 还需显式执行 `node scripts/migrate-reader-profiles.mjs <private-main-data-directory>`。工具先在私有 `schema-backups` 保存完整原库，再在事务内扩宽已有申请表的种类约束并新增审核建议表，保留原行、自定义列、索引、触发器和外键引用，重复执行不再次备份或改表。旧库的正常启动不偷偷重建申请表；昵称提交或建议在未完成迁移时失败关闭，原头像、个签申请仍保留。

主站日常 `scripts/backup-payload.mjs` 新增可选 `profileWorkflow: "durable-v1"` 清单字段，保存持久申请、建议、清理任务、全部待审头像文件和审核文件日志。仅在备份副本中清空短时邮箱验证申请、登录尝试记录，源库不变。备份从开始到结束保持同一主内容库和工作流库只读观察连接，核对 `PRAGMA data_version`、数据库文件身份、审核日志状态及上传文件哈希；期间任何源库写入或文件变化都拒绝生成成功清单，须在较安静的时段重试，不能宣称双库原子快照。业务持续繁忙时先使用既有服务停止手段进入维护，再执行完整备份。

`scripts/restore-payload.mjs` 保持旧清单兼容；新清单先校验数据库、待审头像引用和所有文件哈希，再只恢复到新目录和新配置，不覆盖在线数据。缺少待审图片或未知工作流清单版本直接拒绝；恢复不会重新激活备份时的短时注册申请。香港背景建议与实际审核记录随香港完整业务库和上传备份恢复。正式发布须先在独立恢复目录验证两端数据，再迁移主站、发布主站和香港的匹配审核协议，最后恢复入口并验收。

回退界面时保留两端新版资料审核和权限后端、当前业务库及工作流。已实测前一已提交版本的工作流启动不会收窄新约束，旧审核命令会拒绝昵称申请而不会误当个签或头像；但旧主站资料保存接口会直接改昵称，旧香港管理判断也没有新层级的授权规则。因此不能直接恢复旧运行时并继续开放资料写入。若必须完整回退，先在主站停止 `sansphase.service`，在香港停止 `sansphase-community.service`，保持两端入口和写接口不可用，备份当前数据，再检查或修复运行时；新版恢复后才重新启动和验收。服务名称来自 `deploy/sansphase.service` 和 `deploy/sansphase-community.service`；停止服务复用现有部署手段，未增加业务开关。保留现有HTTPS配置，初次证书的HTTP bootstrap配置不用于当前HTTPS维护。严禁用发布前的工作流或整库覆盖已经上线后产生的申请、建议和审核结果。

备份和过期图片清理均保护已通过、待审背景；已被引用的原图或缩略图缺失时备份失败。账号永久清理按既有规则处理背景引用和图片队列。不要将这些持久数据当旧版本缓存删除。

Nginx 仅对 `/api/community/profile/avatar`、`/api/community/profile/background` 上传放行到 `2112k`，为 2MiB 裁剪文件的 multipart 头留余量，应用仍逐文件限制 2MiB；其它接口不扩大限额。资料接口不开放跨站 CORS。发布代码和迁移都须先在隔离副本验证，保留上一已验收代码及迁移前数据备份。
