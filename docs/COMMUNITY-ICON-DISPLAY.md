# 昵称图标与个人佩戴

2026-10-09 用户确认：昵称后最多显示一枚图标，包括顶部账号、帖子及回复作者、全局排行榜和个人资料卡；移除管理身份文字小牌。个人主页新增“图标”分区，所有人员按实际资格选择，不能冒用管理或 VIP 身份。

未自定义时，默认采用当前有效管理身份，否则采用有效 VIP 最高档，普通用户不显示图标。用户可自行选择已获成长等级、社区等级、有效 VIP 和管理身份、已确认的成就图标，也可不佩戴。已失去资格的图标保留在目录中并变灰；原选择保留，公开显示暂停，不自动换成另一枚图标。

目录复用原有图形，采用静态预览、延迟加载；昵称位置沿用可见范围内的空闲动效，实际滚动时统一显示静态图形，停止约 600ms 恢复。保留图片、动画节点与阅读位置，不在滚动中重新加载素材。

图标按管理、VIP、成长、社区和成就分类，每页最多六枚，分类与翻页只使用当前资格快照，不重复请求接口。确认佩戴只更新选择状态和昵称，不重建整个卡片集合；连续点击由同一身份的写入锁串行保护。

个人主页在“图标”后增加“头像框”分区，只读取既有本人 `GET /api/community/profile` 的已拥有头像框，不读取订单或未兑换商品。已下架但仍合法拥有的框继续可选，佩戴及取下复用 `shop/equip` 的 `kind: frame`；只读预览禁止操作。职务自动框仍优先展示，商城选择独立保存供职务结束后使用，不通过选框获得或失去管理权限。

佩戴复用 `POST /api/community/shop/equip`，增加 `kind: icon`；服务端依据真实资格检查，客户端不得通过提交标识获得职位、VIP、等级、星尘或成就。图标选择与头像框、昵称特效、主页背景分别保存。默认、摘下和显式选择分别存储，迁移只增加选择字段，不改现有业务记录。

上线需要正式新增 `community_members.name_icon` 可空字段，不能按零迁移更新处理。先按 [源码与服务器维护](MAINTENANCE.md) 完成数据备份、异地副本与校验，再运行已有 `scripts/migrate-community.mjs` 入口。原有账号默认值为空，沿用管理身份优先、VIP 次之的默认规则；明确摘下使用空串，不能与默认值混淆。未迁移数据库按现有架构检查拒绝开放社区，不能绕过检查直接启动新版本。

验证覆盖长昵称和管理头像框占位、窄屏入口、暂停及恢复时节点保持、所有身份展示位置、单枚选择、资格失效置灰、认证与越权拒绝、持久化以及迁移幂等。浏览器像素和拖动流畅度仍需实际视觉确认；结构和逻辑回归不能代替视觉结论。
