# 昵称图标与个人佩戴

2026-10-09 用户确认：昵称后最多显示一枚图标，包括顶部账号、帖子及回复作者、全局排行榜和个人资料卡；移除管理身份文字小牌。个人主页新增“图标”分区，所有人员按实际资格选择，不能冒用管理或 VIP 身份。

未自定义时，默认采用当前有效管理身份，否则采用有效 VIP 最高档，普通用户不显示图标。用户可自行选择已获成长等级、社区等级、有效 VIP 和管理身份、已确认的成就图标，也可不佩戴。已失去资格的图标保留在目录中并变灰；原选择保留，公开显示暂停，不自动换成另一枚图标。

目录复用原有图形，采用静态预览、延迟加载；昵称位置沿用可见范围内的空闲动效，实际滚动时统一显示静态图形，停止约 600ms 恢复。保留图片、动画节点与阅读位置，不在滚动中重新加载素材。

图标按管理、VIP、成长、社区和成就分类，分类内一次展示全部对应图标，不分页。宽屏每排五枚、较窄窗口三枚、手机两枚，剩余图标向下排列。分类切换只使用当前资格快照，不重复请求接口。分区只保留分类、图标、恢复默认和不佩戴操作，不重复展示标题、说明或昵称；重复点击当前分类不重建图形。确认佩戴只更新选择状态和昵称，不重建整个卡片集合；连续点击由同一身份的写入锁串行保护。

成就图标按服务端已确认的获得记录，每个系列只展示当前有效的最高材质，不展示同系列较低档或未获得的系列；社区等级、成长等级不能冒充成就获得。此前选择的成就图标如资格被撤销，仍保留为灰色不可佩戴卡片，沿用用户要求的失效提示，不展开整套未获得图形。

个人主页在“图标”后增加“头像框”分区，只读取既有本人 `GET /api/community/profile` 的已拥有头像框，不读取订单或未兑换商品。已下架但仍合法拥有的框继续可选，佩戴及取下复用 `shop/equip` 的 `kind: frame`；只读预览禁止操作。职务自动框仍优先展示，商城选择独立保存供职务结束后使用，不通过选框获得或失去管理权限。

2026-10-09 用户要求收简佩戴区：没有已拥有头像框时返回空内容，不展示空卡片、标题、解释、昵称或商城入口；有框时只展示已拥有框的选择卡片。预览只显示框本身，不混入头像或姓名首字；内置框保留透明圆心，自定义框沿用完整原图。点击选择佩戴，再次点击已选框取下，按钮和框图节点在保存时保留。库存读取失败仍显示既有重试状态，不能把未知库存当成空库存。

佩戴复用 `POST /api/community/shop/equip`，增加 `kind: icon`；服务端依据真实资格检查，客户端不得通过提交标识获得职位、VIP、等级、星尘或成就。图标选择与头像框、昵称特效、主页背景分别保存。默认、摘下和显式选择分别存储，迁移只增加选择字段，不改现有业务记录。

2026-10-09 资格一致性修复：已确认的作者关联个人账号沿用 [独立社区部署](COMMUNITY-HOSTING.md) 中的最高展示，昵称、佩戴目录、成长／VIP 展示和成就展示复用同一份服务端投影。该投影不是实际 VIP、经验或荣誉奖励；直接以个人读者登录时，真实会员及发帖、管理权限仍以实际账号为准。每日访问按最终确认的个人账号及真实会员结算，回执保留其批准的展示等级，不用真实结算进度覆盖装饰投影。

普通账号的会员标志、VIP 档位与图标资格取同次已确认资料。本人缓存帖子、榜单和资料会合并当前会员、社区等级与图标；主动访问只有发生档位变化时才重读当前页面及身份，同档进度不增加身份请求。较早发出的个人页读取不能覆盖后来确认的图标目录；保留用户显式选择和不佩戴，并沿用卡片节点更新。

独立主机的写入最终身份复核会重新向既有主站身份桥读取，不能返回请求开始时的旧快照；读取之后仍核对本地会话、主体及作者个人绑定。身份服务失败拒绝写入，普通身份展示读取仍只核验一次。签到及补签按最终真实会员结算，作者最高外观不增加免费补签或月度次数。本人缓存昵称同步已经确认的新昵称。合法拥有的下架装扮可读取自己的商品图片，即使历史拥有记录没有订单；这不开放其他人的私有图片。

上线需要正式新增 `community_members.name_icon` 可空字段，不能按零迁移更新处理。先按 [源码与服务器维护](MAINTENANCE.md) 完成数据备份、异地副本与校验，再运行已有 `scripts/migrate-community.mjs` 入口。原有账号默认值为空，沿用管理身份优先、VIP 次之的默认规则；明确摘下使用空串，不能与默认值混淆。未迁移数据库按现有架构检查拒绝开放社区，不能绕过检查直接启动新版本。

验证覆盖长昵称和管理头像框占位、窄屏入口、暂停及恢复时节点保持、所有身份展示位置、单枚选择、资格失效置灰、认证与越权拒绝、持久化以及迁移幂等。浏览器像素和拖动流畅度仍需实际视觉确认；结构和逻辑回归不能代替视觉结论。
