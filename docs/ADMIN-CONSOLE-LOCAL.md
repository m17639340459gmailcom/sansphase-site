# 本地管理面板升级

## 本轮边界

主站独立入口 `/admin-console/`。2026-10-12 用户明确：博客原来的作者面板、内容管理、资料与外观设置保留原 UI/UX；新后台的用户、VIP、备注、清理维护与账号记录继续使用。先完成主站，再接社区。本轮完成正式构建、原登录接入和本地数据升级/代码回退演练；尚未发布、未替换线上管理入口、未修改生产数据或社区管理流程。

| 分区 | 已接入的既有功能 |
| --- | --- |
| 主站内容 | 回到原作者面板管理博客文章、作品、资料、软件推荐、资源中心、公告；沿用原列表、草稿、发布、撤回、删除、拖动排序与返回路径 |
| 内容编辑 | 原 Tiptap 富文本、图片压缩与上传、封面、附件、表格与文本样式；原书籍章节编辑与 VIP 阅读设置 |
| 个人设置 | 原作者面板中的个人信息、头像、介绍与社交链接；背景库；音乐；点缀颜色，不另设卡片中转页 |
| 用户与会员 | 用户/VIP 筛选、作者私有备注、显示 UID、最近登录、停用/恢复、撤销登录、VIP 期限及永久删号确认 |
| 资料审核 | 昵称、签名、头像申请及原审核建议 |
| 清理与维护 | 过期注册申请、旧头像、已删除内容的旧版本与附件；精确选择、确认及服务端保护 |
| 账号操作记录 | 现有账号操作日志的近期窗口，包含备注变更事件但不含备注正文 |

原作者面板的“后台管理”进入新版用户管理，新后台的“博客作者面板”返回原作者面板。两者共用同一作者会话。没有新增完整历史审计、版本恢复、数据库或服务器备份管理。社区帖子/举报/兑换/茶室管理仍留在原系统，后续单独接入。

采用 React-admin 5.15.4 免费核心、MUI 7.3.11 和原有 React 19。使用官方数据/认证适配协议与 CustomRoutes，复用 `/api/manage/*`、`/api/author/*` 的领域服务；不直接编辑 Payload 数据表。React Router DOM 7.18.4 从既有相同版本的传递依赖提升为精确开发依赖，供官方自定义路由使用。当前公共网站构建不加载新后台入口。

## 设计约定（brand spec）

模式为恢复并保留原有交互。博客创作与设置直接使用 `author-entry.mjs`、`author.css` 和主站样式，不在 React-admin 内复制、重新配色或重新分组；移除上一版单独的内容表格、设置卡片和编辑器样式覆盖。保护原字段、顺序、焦点、未保存提示、拖动排序和返回行为；视觉变动 1/10、品牌保持 10/10，动效与信息密度沿用原面板。

用户、VIP、审核、清理与记录保留已认可的新后台样式。“無相”文字标识、深蓝、暖金与中文表达保持不变。浅色底 `#f5f3ee`、白色内容面、文字 `#25344a`、强调色 `#785e39`；深色底 `#152235`、内容面 `#1d2d43`、强调色 `#d7bb88`。使用现有中文系统字体，不依赖外部字体加载。

功能优先，信息密度中等，低动效；品牌保持度高。没有装饰性图表、虚构经营指标或无效按钮。现有资料投影接口是数据来源。演示模式使用独立合成库并标记本地预览；正式构建不包含演示登录或演示文案。桌面保留完整表格，手机使用 React-admin 的简洁列表，点击行打开详情；平板表格容器可以横向滚动，外层不溢出。对话框保存失败保留输入。输入框只用原边框变色表示焦点，不叠加轮廓与阴影。

## 契约限制

- 用户列表服务每页固定 20 条且有自己的排序规则，界面不开放无效排序。
- 用户详情从已选择行打开，不虚构不存在的单条 GET 接口。
- VIP、停用、恢复、退出登录和审核均调用原有专用动作；等待服务器确认，不乐观假成功。
- 资料审核仅展示原接口返回的最早 100 条当前待审队列，数量不是全站待审总数。
- 内容列表与编辑器使用原主站入口及原接口，不再存在独立后台编辑器宿主。原有内容发布、保存后刷新、修订冲突检测和未保存提醒全部沿用。
- `/admin-console/#/content`、`/content/:kind`、`/site-settings` 旧本地书签转到原作者面板，不保留重复界面。
- 清理页只展示现有接口的本批数据；单次最多 100 项。失败保留选择，仍在引用、共享、暂缓及失败结果据实显示。历史版本队列仅为已删除内容的清理重试，不能用于恢复内容。
- 操作记录仅为现有日志最后 100 行内筛出的最多 20 条账号操作，没有完整历史分页；备注操作只显示是否清空和长度，服务端投影不带正文。
- 新后台登录失效清理私有页面；退出接口返回 401 表示会话已经过期，仍完成本地退出。博客作者面板继续使用原来的身份与退出流程。

## 作者私有备注

作者可在用户详情的“管理备注”中新增、修改或清空备注；最多 200 个 Unicode 字符，保留用户原昵称。用户管理和 VIP 列表显示备注摘要，搜索同时匹配备注。备注仅加入作者管理接口投影，普通用户、公开资料和社区身份桥不返回该字段。

包含备注搜索的两个列表关闭筛选状态的 URL 同步与浏览器持久化，搜索状态只留在当前页面内存中。保存成功后刷新列表，失败时保留输入；VIP 等其他账号操作不会清空备注。正式发布前需按[备注迁移说明](READER-ADMIN-REMARKS.md)升级 schema，并核对反向代理日志不记录后台搜索请求的完整查询参数。

## 本地启动和验证

使用项目要求的 Node 24.21+，执行 `pnpm preview:admin-console`，打开输出的 loopback 地址。预览从全新合成 Payload 库启动；不读取生产配置，不复制真实用户数据，无邮件发送。演示作者为 `owner@example.test`，密码 `DemoLogin2026!`，仅用于独立预览。

执行 `pnpm preview:admin-console --redesign` 可在 4251 端口打开 V3 重设计版，演示登录完成后进入管理概览。新版顶部的「返回主站」在当前标签页打开 V3 本地首页 `http://localhost:4308/`，需同时运行 V3 预览。侧栏的「博客作者面板」在管理台内直接打开现有编辑器和网站设置。编辑未保存时切换分区会提示确认。新版与 4249 上的经典预览各自使用一套合成数据。正式构建禁用重设计预览开关。

验收 V3 登录、管理台和整本草稿预览时，执行 `pnpm preview:admin-console --v3` 启动另一套合成库和本地滑块服务。在 `previews/frontend-v3/.env.local` 配置 `SANSPHASE_V3_LOCAL_READER_ORIGIN=http://localhost:4315` 并以 `localhost:4308` 启动 V3。在 V3 的 `/account` 登录演示作者后进入管理台，两端使用同一份会话。整本草稿在 V3 阅读器中打开，仅当前演示作者可访问。

每次预览都从正式源码把主站与后台构建到新的临时目录，不复用运行中的 `dist`，也不使用线上静态资源域名。经典预览登录后通过主站既有 `#/account` 路径打开原作者面板。原面板“后台管理”和旧 `#/admin`、`/manage` 已在正式源码中接到新入口，预览不再注入按钮拦截脚本。经典后台的「返回主站」打开同一预览的博客页。书籍编辑器「保存草稿并预览整本」沿用正式阅读器，可检查目录、章节与未发布修改，并需要本地作者会话。

合成预览在独立子进程内运行完整 Payload 服务，正常停止监听、关闭数据库并退出后，父进程才核对路径、删除本次临时目录，避免 Windows 原生驱动在当前进程内残留文件句柄。启动失败也等待子进程退出再清理；关闭错误会明确报出，不冒充成功。若仍有外部文件占用，清理最多短重试三次后报告残留目录。硬性终止父进程可能保留临时目录，不能将其当成正常关闭或承诺强杀也能自动清理。该机制不改变生产数据库驱动。

针对适配层、真实服务和浏览器执行 `tests/admin-console-*.test.*`。设置 `ADMIN_CONSOLE_BROWSER=1` 后，浏览器用例自己启动独立的临时预览和浏览器，完成后关闭；不修改用户正在体验的演示数据，不连接用户现有标签页。主站用例覆盖六类编辑器、草稿/发布/冲突、整本预览与逐章阅读、设置、排序、删除、桌面和手机布局；账号与维护用例覆盖冲突、失败保留、防重复、权限失效与精确清理保护。

`tests/admin-console-release-browser.test.mjs` 使用工厂的显式 `deliveryVerification` 参数启动另一份合成库，采用正式后台构建、原登录表单、实际服务端 proof/nonce/单次使用检查和真实密码/权限服务。只有私有拼图判定引擎是可重复的测试替身，不能据此宣称完成了线上 Java 拼图引擎或抗脚本能力验证。此模式禁用全部预览快捷登录，验证密码请求缺少凭证时拒绝、作者原面板往返、主动退出、失效会话、网络故障重试以及普通读者隔离。生产运行时不引用此工厂或演练参数。

## 正式交付接入

- `build-site.mjs` 调用独立的 `build-admin-console.ts`，把管理 HTML、JS、CSS 和实际依赖许可证写入全新的 `admin-console/`。访客页面与 CDN 场景资源清单不加载管理包；构建默认剔除演示分支。
- `verify-site.mjs` 检查入口及其完整依赖。使用既有 esbuild 解析真实 JS、动态导入、CSS 和图片引用，缺少资源、越出管理目录或依赖外部资源均失败。正式启动的 manifest 校验也要求后台三个入口存在。
- `/admin-console/` 的静态壳不含用户数据；React-admin 渲染私有页面前检查作者会话，既有 `/api/manage/*` 再次独立鉴权。HTML 不缓存并设置 CSP、防嵌入和禁止索引；社区专用服务对该目录、旧别名及编码分隔符变体返回 404。
- 未登录时进入原 `#/account` 表单及既有人机验证；`adminReturn` 只保留五个明确分区，不携带私有搜索或任意 URL。普通读者误入后留在原账号页，不获得后台访问权。
- 明确失效会话清理本地私有状态；网络故障提供重试。React-admin 的自动鉴权失败不得撤销服务端有效会话，只有实际点击退出才调用退出接口；迟到的并发响应不能覆盖已确认的身份失效。
- 按[备注迁移说明](READER-ADMIN-REMARKS.md)执行显式升级。合成数据演练包括备份、恢复到另一个新目录、`push:false` 缺列拒绝、幂等迁移、旧代码使用同一个新库以及切回新代码；不通过还原旧数据库来模拟回退。

## 查询参数依赖的安全适配

React-admin 5.15.4 的 `ra-core` 和 `ra-ui-materialui` 原依赖 `query-string 7.1.3`，其 `decode-uri-component 0.2.2` 存在畸形百分号输入造成耗时过长的已公开问题（[GHSA-vcc3-ghjq-m6fr](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr)）。安全范围中的 `>=0.4.3` 不代表存在 0.4.3 发布包；实际修复版本为 0.5.0。

这两条依赖限定升级到官方 `query-string 9.5.1`，使用其 `decode-uri-component 0.5.0`。新 query-string 默认导出与 React-admin 的命名导入不同，因此 `patches/query-string@9.5.1.patch` 仅在包入口及声明入口各增加一行 `export * from './base.js';`，把上游原函数重新导出。没有复制或自行实现解析算法，也没有改其他消费者的依赖范围。

`tests/admin-console-query-compat.test.ts` 核对两个实际消费者的依赖版本、Node CJS/ESM 导出，以及实际 React-admin 列表 URL 解析器的浏览器构建，覆盖中文与符号、重复键、空值、无效筛选 JSON、原型属性名和大量畸形转义输入。后续升级 React-admin 时应先复核上游依赖和导出契约，再决定移除这个兼容补丁；不能仅凭 audit 清零判断兼容性。
