# 社区上线前讨论与身份预览

2026-10-06，基于当前正式源码及独立测试环境检查。独立作者/版主管理页、商品图片、管理账号的读者浏览视角、请求去重、持久限速、管理审计及已确认的星尘获取规则 v4 已纳入源码。下方区分已完成的防护、验证边界和上线待办；没有部署或操作生产数据，也不表示多账号互刷已全部解决。

## 正式账号与本地开发身份

正式社区通过现有登录会话及 `GET /api/community/me` 识别账号。仅作者、作者任命且有有效负责板块的版主可以切换读者浏览视角；普通读者没有身份切换和管理台入口。账号菜单不展示独立样例身份选择页。

开发复现可从正式源码运行 `scripts/catalog-fixture-preview.mjs`，手动访问 `/api/community/preview-identity` 选择三种样例账号。示例端口为 4215，实际地址以启动输出为准；此工具不向社区账号接口注入入口。选择任一样例身份后统一返回社区首页，管理台必须通过账号菜单点击进入。

身份选择使用现有 `preview_as` 样例账号 cookie。仅本地样例服务挂载，校验本机地址、Host 和切换表单的 Origin；正式社区运行时仍使用真实登录会话，不读取此 cookie。发布源码清单包含预览工具供复现，但正式启动流程不会挂载身份选择接口。

| 身份 | 现有权限及入口 |
| --- | --- |
| 读者 · 预览读者 | 发帖、回复、签到、兑换；不能进入社区管理 |
| 作者 / 站长 · 無相 | 社区管理全部分类，兑换物品上架、发货和取消订单、任命协管；可评精华 |
| 版主 / 协管 · 守望 | 只管理作者分配板块里的帖子、待审和举报，查看这些板块的数据；移动要求来源、目标板块都属于负责范围。按用户选择，保留全社区禁言与解除权限；不能上架、发货、查看收货信息、任命版主或评精华 |

作者、版主处于管理身份时，右上角账号菜单显示“管理台”，点击打开 `#/community/manage`；切换身份本身不打开管理台。这里的作者是网站作者/站长；普通读者作为帖子作者，只管理自己的帖子，不因此取得管理权限。

本地样例「守望」显式负责学习问答、工具资源，用于展示板块分工；这不是对正式账号的任命或权限修改。

## 社区公约与公开联系入口

本地已补齐六章公约：交流内容、板块发布、星尘成长、兑换装扮、账号数据、管理申诉。固定导航进入 `#/community/rules`；板块标题、发帖底部、星尘规则和兑换所另提供相应入口。公约、联系入口、社区内容及管理地址均要求登录。位置与参考来源见 [社区公约与规则入口](COMMUNITY-CONVENTION.md)。首次进入社区显示公约弹窗，底部确认按钮满 10 秒才能点击；作者在管理台“社区公约”修改并发布后，所有成员需要重新阅读与确认当前版本。服务端验证版本和阅读时间，不接受旧的无版本同意或发帖勾选。

作者沿用已有 QQ 联系链接。作者和现任版主在管理台“联系设置”自愿填写本人 QQ 或公开联系邮箱，两项均可留空。资料与注册邮箱／手机号分开；公开联系人显示负责板块，已登录的成员可读取，禁言不妨碍联系作者或版主；未登录请求拒绝，撤任后停止公开并清空自愿资料。其他社区 API 的登录边界不变，任命仍由作者负责。

新增 `community_members.contact_qq/contact_email/agreed_version/convention_read_version/convention_read_at` 字段及 `community_conventions` 版本表，纳入原有显式社区迁移、备份及幂等校验；启动服务不会修改数据库结构。正式上线前需要随社区迁移执行，不可只替换前端产物。

同时修正了兑换所和确认框中“一律不能退回”的旧表述：作者取消待发货订单退还星尘，读者没有自助退款入口。禁言提示及板块须知改为实际可用的作者／版主联系方法。

作者管理导航提供「版主管理」（`#/community/manage/stewards`）。输入读者 UID、查找并核对昵称后，勾选一个或多个负责板块再任命。现任名单显示负责板块，可展开调整或撤销。名单使用现有 `GET manage?tab=stewards`，任免与调整复用 `POST members/:uid/steward`；任命及调整必须提交显式非空、无重复的已知板块列表，服务器限制为作者。版主本人不能任命其他版主；读者浏览视角也不能操作。旧委任的空数据库字段兼容为原有全板块权限，不会静默缩减；损坏或非法范围数据按无管理权限处理。

左侧「待审」「举报」合并为一个「内容审核」入口。页内顶部两张任务卡切换待审内容与举报，保留现有路由兼容及板块选择、阅读位置；深浅模式共用明显的选中颜色。作者可选全部板块，版主只显示自己负责的板块；服务器同时过滤内容、计数和统计，不依赖网页隐藏按钮。进入其他管理分类后重置筛选。批量审核只针对当前筛选中可见待审帖子，每批最多 50 个；服务器先检查整批状态和板块权限再操作，混入越权帖子时整批拒绝。切换板块清空已选帖子。已删除且无法判定板块的举报只有作者可见、可处理。

委任身份与真实信任等级分开：版主标识保留，但普通发帖限额、先审规则、图片数量、互动规则、感谢、编辑期限和兑换门槛按实际信任等级执行。指定负责会员茶室的非 VIP 版主可以读取及审核该板块，不能因此获得普通 VIP 发帖、回复或兑换权益。隐藏帖子、回复正文、引用、提及和图片按负责板块检查；读取期间撤权后不继续返回管理内容。管理写请求提交完整内容后重新验证当前委任，范围变更或撤职不能让尚未提交完的旧请求继续审批、禁言或解除。

同一浏览器标签页共享模拟身份，切换后其他社区标签页要刷新。身份和操作只影响临时样例数据库；重启预览会重新生成样例数据。该预览不模拟真实作者登录及主站内容发布面板。

## 独立管理及浏览视角

右上角入口统一称为“管理台”，`#/community/manage` 地址保持不变。管理页使用专用导航与完整工作区，不进入普通社区三栏；深浅模式共用结构、字号和控件。作者拥有商品及订单管理，版主只显示其已有权限分类。“帖子管理”提供最近 100 条已公开内容，待审和自动隐藏内容保留在待审分类。

所有作者/版主的删除接口，包括举报成立后的删除，要求填写 2–200 字理由。理由保存于内容记录及审计记录，原作者收到带理由的通知；违规扣罚仍遵循已有规则，普通用户删除自己的内容不因此增加管理权限。

账号菜单提供“以读者身份浏览”及对应的“返回作者身份”／“返回版主身份”；管理导航保留“以读者身份浏览”。这是保留真实账号的只读视角，不是登录其他用户：服务器屏蔽管理、VIP 和作者专属提示词权限，并暂停写操作；可以随时从账号菜单返回。身份切换会清空旧管理缓存，迟到的请求不能把旧权限数据放回页面。`community_browse` cookie 不会给普通读者授予任何权限。

普通读者在自己的真实账号下可以正常签到，同一天只结算一次奖励。作者本身不参与签到，切换读者视角也不会改变这一资格；版主在真实管理身份下仍可按读者规则签到，切换读者视角后只能查看月份与签到记录，不能签到或补签。网页提示与服务器限制按真实账号及浏览视角一起判断，伪造浏览 cookie 不能把普通读者变成管理账号。

公共内容页切换视角保留当前地址、阅读位置及新帖/回复草稿；从管理台切到读者视角返回社区首页。现有帖子/回复编辑及商品编辑须先完成或取消，再切换视角，避免丢掉没有独立草稿的编辑表单。旧账号请求返回后不能刷新或提示新的账号会话。

每次重新打开网址或刷新页面默认深色；本次浏览内手动切换明亮后，社区内容页与管理台统一跟随，路由、语言切换不会重置。主题只保存在本次页面的内存中，不恢复旧 URL 参数或长期存储值，也不影响主站主题。

成长等级独立于原有信任等级与版主任命，共有 G1 星芽、G2 星火、G3 拾光、G4 寻星、G5 观星、G6 巡星、G7 织星、G8 引星、G9 星河、G10 星海十个称呼。真实读者的昵称、账号菜单及个人页显示成长标识，作者不参与；等级页已改为单个等级预览：左侧切换、右侧说明，成长与社区权限分开查看，不再纵向铺满，也不显示图标来源入口。当前只启用 G1 注册起点，[独立经验方案](COMMUNITY-EXPERIENCE-RULES.md)已按 QQ 活跃积累思路提供页面草案，并按用户确认的“最快至少 3 年满级”设定节奏。按后续“提高获得经验数值、只调整比例”的要求，奖励和门槛统一乘以 10：每日最多 60 经验、G10 累计 72,000 经验，理论最快仍为 1,200 个达标日。经验结算、历史衔接和冲正边界尚未实施，不运行自动成长升级，也不显示推算的百分比。成长称呼不授予审核权限，商品兑换门槛继续使用原有信任等级；星尘获取规则 v4 已实施；经验结算与历史衔接仍须在上线前落实并补充验证，不能用旧信任等级或星尘统计替代。

新增 VIP 加速已确认八档 VIP1～VIP8，并按最新更正只累计有效会员登录日数自动升级：未登录日既不增加 VIP 成长日，也不增加 G 等级经验，签到不是前置条件。VIP8 需累计 1,095 个有效会员登录日，每天登录才约需三年；已持有 VIP8 后每日登录即可一年内达到 G10，不要求内容贡献。具体草案见同一份经验方案：VIP8 登录每日 200，360 个有效登录日可到 72,000；主题、回复、采纳及星尘不乘 VIP 倍率。会员有效期照常流逝，缺席日不补计，累计 VIP 成长日后判断新档位再发当日经验。普通用户的三年节奏不适用于 VIP 加速用户。当前正式源码仍只有 VIP 有效期，没有八档结算、有效会员登录日或独立经验结算；等级页已增加 VIP 倍率目录和标记为待启用的进度条，不显示升级计算规则，也不编造个人档位和进度。未启用任何新权益。实施前必须补齐真实登录记录、经验独立流水、日期去重、到期/续期、历史衔接与并发回归，不能以离线时间增长代替。

商品支持单张 JPG、PNG、WebP、GIF 上传、预览、替换、移除；GIF 和动态 WebP 转换后保留帧数、时序。只有作者可上传和保存商品图，沿用作者 25MiB 技术上限，动态图最多 120 帧、总解码像素最多 4000 万。社区普通用户与 VIP 的图片上限继续为 2MiB。商品图单独标记用途，不能冒作帖子附件；已经关联商品的图（含下架商品）不会被未使用上传清理。下架后作者和已兑换该商品的成员仍可查看商品图。

作者在“兑换所上架”中新增商品分类，再选择实物、数字资源、头像框装备或昵称特效。分类仅用于陈列，不改变兑换用途与已有权益。头像框拖入正方形 PNG / GIF / WebP，服务器验证每一帧的中心透明区域与边缘有效内容；普通展示图不能直接作为头像框。昵称拖入制作好的 `.json` 效果文件，支持单色、双色渐变和流光渐变的受限配置，不上传任意代码，也不在上架页编辑颜色。文件上限 64KiB，导入及服务器均校验样式和颜色。上架前可看佩戴预览。

装扮兑换后自动换上，也可在“我的兑换”换上或取下。自定义装扮沿用已有余额、库存、归属和装备接口；下架不收回已兑换装扮，仍在佩戴的头像框可以被其他成员看到。已兑换的头像框不能替换为另一素材；需作为新商品上架。昵称效果在帖子、回复、个人页、通知、排行榜及账号栏共用渲染，并为深浅主题调整可读性；换装后返回缓存页面使用当前账号的最新装扮。

待审帖子支持勾选和批量通过／不通过，每次 1–50 帖。不通过需选择理由，可补充说明。服务器在同一事务先检查整批待审状态与权限；任何帖子已处理时整批拒绝，不部分执行或重复奖励。提交中锁定批量与单条审核，避免重复点击。

管理页的加载与完成状态保留同一导航、统计槽位；表格操作按钮统一对齐、间距和确认宽度。发货、删除与审核理由使用固定弹窗，不把表格向下挤开。弹窗遮挡背景操作，支持键盘循环、取消及 Escape 返回触发按钮。商品表单按类型显示相关字段，不混入无关快递或下载字段；深浅模式共用布局。

社区同页交互统一保留阅读位置，包括管理页板块筛选、横幅位置切换、列表更新和弹窗。加载时临时保留页面高度，避免短暂占位内容把浏览器滚动位置压回顶部；完成后释放留高，最终结果较短时停在最近可用位置，不保留整段空白。用户主动滚动优先，迟到的旧请求不能把新页面拉回旧位置；恢复输入焦点不自动滚动。真正进入另一页面仍从顶部开始，审核与举报的明确内容切换沿用现有位置保留规则。

首页与各板块横幅独立配置：首页只有作者可以修改；作者可修改所有板块，版主只可修改作者分配的板块。每处最多 5 张、正常浏览时每 5 秒切换。按最新确认移除箭头、计数和暂停控件及占位；保留原生滑动、方向键与悬停、焦点、拖动、页面隐藏和减少动态效果的暂停规则。管理页由所选板块按钮显示当前位置，不重复展示位置说明面板。编辑、封面上传、并发版本冲突及发布边界见 [横幅维护说明](COMMUNITY-BANNERS.md)。

作者和版主的读者视角不再显示整条浏览提醒，也不在签到位置重复提示；返回作者／版主身份继续使用账号菜单。只移除显示，不放宽服务器的只读权限。内容按钮恢复焦点时不滚动，发送回复不自动跳到新回复。管理页与普通社区框架都在替换内容前保留临时高度，防止加载占位导致先归零、后恢复；内容就绪后释放，较短结果停在有效范围内。禁用社区的浏览器滚动锚定，移除按重建按钮位置补偿滚动的旧分支。

按用户更正，处罚记录继续保留，不设置一周删除。记录页显示最近 100 条，区分执行中、已到期、已解除；仅执行中的处罚提供解除操作，统计待处理数量不包含历史记录。

正式上线前必须按维护指南备份并执行 `scripts/migrate-community.mjs`，补齐商品图片、图片用途、删除理由、商品分类、装扮类型／昵称配置、头像框验证标记、横幅配置，以及本轮 `community_requests`、`community_rate_events` 和 `community_audit_events` 表。旧商品与已兑换权益保持兼容。当前仅在独立临时数据库验证迁移，未迁移生产数据库。

| --- | --- | --- |

5. **业务规则与未启用能力。** 星尘获取已经按确认的 v4 实施；兑换建议价格、实物兑换资格、星尘过期与冻结／完整追缴方案没有取得确认，未写入业务。成长经验与 VIP1–VIP8 自动晋级当前明确关闭，页面仅浏览等级和倍率，不显示或伪造个人经验、会员档位及进度。具体经验草案和历史数据衔接见 `COMMUNITY-EXPERIENCE-RULES.md`；上线前若继续关闭，应保留准确的状态说明，不能将草案当作已实施。
6. **真实浏览器页面验收。** 深浅主题、窄屏、拖拽文件、装备动效、下拉及弹窗可读性、同页滚动和键盘操作需要实际页面检查；JSDOM 与源码检查不能替代这一步。最终合并版本还需执行类型检查、相关回归及干净构建，记录实际结果后再交付上线包。

## 尚需业务决定的反刷策略

- 是否对异常兑换暂缓发货、冻结可消费星尘或追缴互刷收益；哪些收入受限、延迟多久、新用户权益和误判申诉需由作者决定，本轮没有默默加入冻结或延迟规则。
- 如何关联用户流水、异常互动及兑换订单，并按注册年龄、互动集中程度、操作速度等组合信号人工复核。学校、家庭和共享网络可能共用 IP，不应仅凭同 IP 判定多账号归属。
- 风控页面及操作权限如何分配。作者继续负责任命、物品、库存与收货信息，版主以其指定板块的内容管理为主；新增工具不得把真实手机号、邮箱及收货地址暴露给无权人员。
