# 社区公约与规则入口

2026-10-06，本地版本，未部署。默认条例位于 `src/community-convention.ts`，奖励数字来自共用的 `src/community-rules.ts`。作者修订的版本保存在社区数据库，规则页与首次阅读弹窗都读取同一份当前正文；独立规则页地址为 `#/community/rules`。

## 放置方式与依据

参考的是入口和内容组织，不照搬其他论坛的处罚、等级或积分数值。

- [Discourse 官方：设置 FAQ 与 Guidelines](https://meta.discourse.org/t/customizing-faqs-and-guidelines/286911)：固定导航进入独立规则页，内容使用清楚的分节。
- [LINUX DO 社区规则](https://linux.do/guidelines)：规则页集中说明交流、账号和管理事项，并标明更新时间。
- [TapTap 官方版主管理板块规则](https://www.taptap.cn/moment/527891387933264636?group_id=330015)：社区通用公约与板块要求配合使用。

本项目采用以下入口：

| 位置 | 内容与用途 |
| --- | --- |
| 社区固定侧栏；窄屏导航菜单 | “社区公约”，固定进入独立规则页。桌面借用同一个导航节点，恢复窄屏时放回原处，不增加重复菜单。 |
| 每个板块的标题区 | “板块规则与版主联系”，进入公约；板块章节说明各板块用途，联系名单注明负责板块。 |
| 发帖表单底部 | 保留公约地址；同意统一在首次进入社区的公约弹窗底部完成，不再提供首次发帖的快捷勾选。 |
| 星尘中心 → 规则 | 完整奖励条件、上限及流水说明，另链到社区公约的账号与行为规定。 |
| 兑换所底部 | 链到公约的兑换与装扮规定；具体价格、库存、注册年龄、等级和限购以各物品展示为准。 |
| 禁言提示 | 进入公约查看作者和对应版主的联系方法，不再引导被禁言者发站务帖子。 |
| 作者／版主管理台 → 联系设置 | 本人自愿填写 QQ 或公开联系邮箱，两项均可选；留空保存即取消公开。 |

公约及联系入口均要求登录。首次进入社区显示公约弹窗，底部确认按钮倒计时满 10 秒才可点击；不能通过 Escape、点击遮罩或旧发帖勾选跳过。这里没有增加私信系统或新的处罚档位。

## 公约修订与版本确认

作者通过管理台“社区公约”修改并发布正文，版主不能修改。支持安全 Markdown 的标题、段落、列表和链接；不接受 HTML 或可执行链接。相同正文保存不产生新版本；带旧版本的并发修改拒绝，避免覆盖他人修改。

- `GET /api/community/convention` 返回当前 `{version,body}`。
- `POST /api/community/convention/read` 提交当前 `{version}`，服务端记录本账号开始阅读的时间；同版本重试不重置服务器计时。
- `POST /api/community/agree` 提交 `{version}`，服务端检查当前版本及至少 10 秒的阅读间隔。前端使用单调时钟保留完整十秒按钮限制，不依赖电脑日期准确。
- `POST /api/community/manage/convention` 仅作者可发布 `{version,body}`。发布实质修改后，作者本人、版主及读者都须重新阅读并同意；旧同意记录保留但不代表接受新版本。

所有社区写操作要求同意当前版本；开始阅读、确认和切换管理浏览视角除外。慢请求在落库前也复核，不能在作者更新条例后继续使用旧版本授权。新默认条例、版本数据及阅读确认字段纳入显式数据库迁移，不能只替换前端文件。

## 面向读者的公约内容

页面使用六个编号章节，标题、列表和板块表分层显示；深浅模式沿用社区颜色变量。

1. **交流与内容。** 对事不对人，尊重新手。不攻击、侮辱或骚扰他人。允许 AI 辅助，但应核实内容、说明作品来源，不批量生成无意义回复。不发广告引流、招揽、诈骗、盗版或破解资源。不公开他人私人资料，截图先打码。引用注明来源并遵守授权，不抄袭、冒名或编造体验。
2. **板块与发布。** 学习问答写清问题、环境和尝试；作品展廊分享自己的作品、工具和做法；工具资源附官方来源和适用条件；随想保持简短；站务反馈用于公告、建议与未禁言时的处理异议；会员茶室按 VIP 与指定管理权限开放。当前发布表单需要至少一张正文图片，首张作封面。作者之外每张图片最多 2 MiB，VIP、版主同样适用。新读者每天最多 2 个主题、10 条回复，前 2 个带图或链接的主题先审后发。首次进入社区阅读至少 10 秒并确认同意当前版本公约，不重复刷屏或凑奖励。
3. **星尘与成长。** 内容贡献为主，签到少量奖励，按北京时间结算。签到每天 +1，有效 VIP 每日签到额外 +1，自然月满勤另 +5；主题 +2、有效回复 +1、采纳 +3，各每天一次，三项共享每日 6 上限。有效回复至少 10 个可见字符且不在自己的主题内；首次精华 +15，每人每月最多 2 篇。点赞、举报、浏览、管理操作不奖励；补签不补发当天普通或 VIP 星尘，奖励撤销不重新开放名额。禁止脚本、多账号互刷和虚假采纳。正常转入与系统奖励分开记录。成长称呼不授予版主权限；升级门槛未启用。完整计算条件见星尘规则页。
4. **兑换与装扮。** 条件以物品实际展示为准。装扮兑换后在“我的兑换”使用或卸下，不改变管理权限。读者没有自助退款入口；作者可以取消待发货订单并退还星尘。收货资料仅作者可见，发货或取消后删除，不在公开帖子中填写。
5. **账号与数据。** 注册邮箱验证码验证，昵称 2–8 个字符，不冒充作者或版主。同 IP 累计最多登录 3 个不同读者账号，重复登录同一账号不增加名额，删号不释放名额，作者不受此限制；多人共用网络可能受到限制。非有效 VIP 连续六个自然月未登录，账号及相应帖子、图片、星尘、兑换数据会永久清理，余额或帖子不豁免；随主题删除的回复也不保留，请自行保存重要资料。有效 VIP 在有效期内保留。安全登录历史、不可复用编号和必要的管理审计不随普通账号数据立即清空。
6. **管理、处理与申诉。** 作者任命版主并指定一个或多个负责板块；审核、删帖、举报处理受板块范围限制，全社区禁言影响所有板块。作者负责物品、发货和任命。违规删除说明理由，按关联流水收回奖励，并另扣 20 星尘，余额最低 0；自行删除、公开前审核拒绝和账号到期清理不等同于违规处罚，已消费或转出的奖励不能保证全部追回。处理记录保留。禁言期间不能发帖或回复，包括站务反馈。有异议可联系作者或对应板块版主；未禁言时也可通过站务反馈说明。申诉提供帖子地址、处理时间与理由，不公开私人资料、不用小号绕过禁言。修订通过站务公告说明。

上面的数字记录本次已实施规则。以后奖励配置变化时，应核对这份文档；页面本身直接使用公共规则配置。尚未确认的兑换新价格、成长门槛、星尘过期、冻结或完整追缴机制不作为已实施规则写入。

## 联系方式的数据与权限

作者复用已有 QQ 联系链接。版主联系方式不是注册资料：单独存入 `community_members.contact_qq/contact_email`，只接受本人主动填写的 QQ 和联系邮箱；不从注册邮箱、手机号或收货信息复制。

- `GET /api/community/me`：本人的 `moderationContact`；普通读者为 `null`。
- `POST /api/community/me/contact`：仅作者和现任、有有效板块范围的版主可写自己的资料，返回 `{qq,email}`。保持既有请求来源校验、浏览视角限制、限速和审计；不能指定其他 UID 或修改任命范围。
- `GET /api/community/moderation-contacts[?board=qa]`：登录后可用的联系人读取入口，已登录的禁言者也可查看；返回公开 UID、名字、作者标记、负责板块，以及主动填写的联系方式。其余社区接口继续要求登录。撤任后停止公开并清空自愿联系方式，重新任命不会自动重新公开。

正式数据库需要按原有显式迁移流程增加联系字段、公约版本表以及每个账号的阅读时间与同意版本字段，不能由服务启动偷偷补结构。本地预览使用新建临时库，不能作为生产迁移已完成的证据。

## 验证边界

回归覆盖公约的六个章节、正确入口与同意动作、导航节点借用／恢复／重建、未登录请求拒绝、十秒确认、修订后重新同意、负责板块、联系方式输入、本人修改、撤任及慢请求期间撤任、重复保存、清空以及格式和输出安全。

这份本地公约和联系方式功能不代表已经部署，也不能替代正式环境的备份、迁移、代理／SMTP 验收和真实浏览器深浅模式检查。
