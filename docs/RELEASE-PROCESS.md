# 正式版本与公开仓库

目标仓库：m17639340459gmailcom/sansphase-site，公开。正式域名：www.sansphase.com。

## 一个源码入口

修改 src、server 及共享模块 → pnpm build → pnpm test → pnpm release:prepare。不要编辑 dist，不要用网址中的 v 参数冒充实际运行版本。

构建先在空目录完成校验，再替换 dist。build-info.json 记录版本、内容摘要和每个公开文件的 SHA-256；正式启动校验清单，/healthz 返回运行版本。健康检查不返回账号、数据库路径或异常详情。

## 公开前准备

release:prepare 使用 scripts/publication-files.mjs 的明确清单复制源码到新的私有临时目录，并检查已知私有值、凭据格式和禁入目录。它不执行 Git 提交、不上传、不修改真实数据库。

保留测试是为了防止回归：tests 下的假数据只用于隔离测试，不进入浏览器构建。早期飞船、旧版宇宙、Directus 启动及提取脚本已移到 archive/release-cleanup-20260915，保留本地恢复记录，不进入公开仓库。不要把历史测试当成当前功能的通过数量。

公开内容包括源码、锁文件、当前功能测试、必要素材、许可证和部署说明。以下不公开：.local、dist、outputs、archive、cms、.preview、旧迁移导出、账号说明、私有上传、数据库、备份、浏览器资料和开发截图。

Git 提交只添加发布准备清单和明确的维护源码；不能直接 git commit -a 或 git add .。2026-09-27 已整理原暂存区，将生成文件移出 Git 跟踪，磁盘副本保留。公开推送仍需明确授权。公开仓库不应包含真实内容数据库或软件安装包，后者通过作者模式管理。

## 每次上线

1. 构建与当前测试通过；用新目录验证一次完整源码构建。
2. 备份数据库、上传文件和私有配置，核对完整性；将备份另存到服务器之外。
3. 从准备清单创建空的版本目录，在服务器上安装 Linux 依赖，不能复制 Windows node_modules，也不能复制旧 release 整棵目录再打补丁。运行依赖、源码及新构建产物之外的发布准备副本、测试数据、输出截图不能继承进版本。
4. 用隔离数据验证新版本，再切换 current 链接，重启服务。
5. 检查 /healthz 版本、匿名与作者权限、发布撤回、下载、刷新及手机页面。失败则切回上一代码版本；若改过数据结构，还需经过验证的数据回退方案。
6. 线上验收通过后完成容量整理，不能把仅清理本次暂存目录视作全部收尾。按下方保留规则核对全部旧版本与备份，记录清理前后可用空间，再复查线上功能。

生产数据始终放在代码目录之外。构建、回滚代码和删除旧版本均不能删除生产数据库。

## 上线后的文件保留规则

用户已要求释放服务器空间，避免堆积无用版本和文件。每次正式上线验收后执行以下维护步骤：

- 完整代码目录通常只保留当前运行版本和上一份已验证、可回退的版本。通过 `current`、运行进程、systemd/Nginx 配置和保留目录中的符号链接确认引用；存在引用、未通过验收或回滚依赖未理清的目录不能删除。
- 保留最近 3 份已验证的完整备份，并额外保留最近 14 天全部备份。按备份清单的 `createdAt` 排序，不能按包含用途名称的文件夹字典序判断新旧。删除之前校验保留副本的文件哈希和数据库完整性；无法识别创建时间的备份不自动删除。
- 部署上传包、隔离测试数据和测试配置在验收后清理；审计回执保留在私有维护目录中。对明确清单执行删除，检查绝对路径、目录身份、挂载点及运行进程引用，不使用无边界通配符删除。
- 生产数据库、上传文件和私有配置属于保留数据。图片与音频缓存能减少访客等待，不因清理旧代码而一并清空。安装包缓存可按需清理，不能把软件运行依赖当作缓存卸载。
- CDN 的旧静态资源可能仍被已打开的页面引用，至少保留 30 天过渡期；当前版、回退版及仍有引用的资源持续保留。不能把旧代码目录的删除清单直接套到 CDN。
- 清理后校验保留文件、数据库和公开内容，检查健康版本以及浏览器实际加载，记录释放空间。无需为普通文件清理重启网站。

每日备份脚本仍只负责生成备份。独立的 `sansphase-maintenance.timer` 只负责验证后轮换过期备份，其他类别须在每次上线验收后核对计划执行；详见 [维护说明](MAINTENANCE.md)。
