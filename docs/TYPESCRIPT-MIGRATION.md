# TypeScript 本地迁移记录

本迁移仅改变源码及构建检查，不改变生产数据库结构、持久目录或已发布内容。未经用户单独同意，不部署或推送到公开仓库。

## 目标与边界

- TypeScript 成为前端与服务端业务模块的主要源码；运行脚本、第三方原始代码等在有理由时可保留 JavaScript。
- 浏览器仍接收构建后的 JavaScript。Node 24 对服务端 `.ts` 使用内置类型剥离，`tsc --noEmit` 在构建前负责严格类型检查；不使用需要运行时转换的 TypeScript 语法。
- 保持现有文章、账户、VIP、头像、上传文件的数据格式及读写流程。迁移中不运行生产数据迁移。
- 每批先确认已有行为测试；缺少关键用例时先补测试，再改源码。每批运行类型检查、构建及相关测试，阶段结束运行全部测试和独立数据库集成验证。

## 已完成的本地批次

1. 基线：迁移前 `pnpm build` 和 339 项 Node 测试通过。
2. 建立严格 TypeScript 检查并纳入 `pnpm build`；发布清单包含配置文件，私密值扫描覆盖 TypeScript 源码。
3. 服务端：文件分段、访客 IP、VIP 时间、内容长度、文件哈希、读者 UID 和短期注册及审核工作流改为 `.ts`，由 Node 24 直接运行。短期工作流的数据库表、加密格式和清理时限不变。
4. 浏览器：公开访问规则、图片地址、静态资源地址、路由与筛选工具，以及作品、资料、软件推荐和资源中心共用的目录展示逻辑改为 `.ts`；构建生成原有 `.mjs` 地址，源码中的 `.mjs` 仅作为 Node 测试适配层。UI、博客星空和首页宇宙入口改为 `.tsx`，由现有 esbuild 打包。
5. 类型检查、构建、342 项完整测试及本地首页、博客、文章、资源中心与作品页预览通过；当前批次尚未部署。
