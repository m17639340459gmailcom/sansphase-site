## 代码检查与清理结果

- 对全项目 TypeScript 检查范围增加 `noUnusedLocals` 和 `noUnusedParameters`，已纳入日常构建。发现的两处必要位置参数分别是编辑器旧状态和禁用的纵向轨道参数，标为 `_old`、`_y`，保留第三方回调/调用方的参数位置，不能直接删除。
- 删除黑洞全屏三角形不再使用的 UV 属性和 shader varying。此前总时间累积扭细、四条额外子光线及旧距离采样估计，均已被当前实现替代，不存在并行运行的旧分支。
- 发现旧玻璃包装仍挂载、创建两张离屏缓冲，但当前页面没有玻璃装置/光标管线消费它们。先补依赖图回归并确认失败，再移除包装层。保留黑洞自身双输出缓冲、天空烘焙、正常后处理和当前照片背景。
- 将六个旧模块从正式 `src` 移至本地忽略目录 `archive/retired-visual-20261001/src`：`library-glass.jsx`、`library-opening.jsx`、`library-spatial-effects.jsx`、`library-nebula.jsx`、`library-orbital-particles.jsx`、`reference-pointer-projection.mjs`，共 834 行。移除仅供它们使用的 `referenceReveal`。旧源码可从 `ac16590` 恢复；本地归档是历史参考，不是独立可运行源码入口。
- 两份旧测试（玻璃折射通道、旧光标投影）随旧功能归档，共 3 个旧用例。没有删减当前注册、权限、VIP、文章、导航、黑洞交互测试。新增依赖图约束防止旧模块与旧玻璃 shader 再进入正式浏览器包。
- 构建图确认旧玻璃模块/shader、本地预览均未进入。新版所有黑洞模块均有实际引用；保留必要 `.mjs` 类型源码兼容入口、许可证、第三方原件及当前复用的星空 shader，不能按文件名“旧”字样批量删除。
- 自有 src/server/scripts 扫描未见冲突标记、`debugger`、`@ts-ignore` 或 `@ts-nocheck`。不是第三方全部源码逐行审计，不据此声称全仓库不存在任何无用导出或安全风险；本轮深入复核的是变更链路和确认断开的旧效果链路。

## 上线判断与剩余边界

本地功能、构建与清理检查未发现阻止进入正式发布流程的问题。发布前仍须固定源码提交，完成生产一致备份及异地校验、Linux 全新目录构建/测试、隔离副本验收、CDN 文件校验，之后才切换并复查健康、真实内容和权限；异常时回退旧代码。

本轮只读检查线上健康，没有访问或修改生产数据库，没有执行部署、服务器清理或公开推送。本地目录清理不会取代上线前数据备份和回滚步骤。
