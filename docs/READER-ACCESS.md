# 读者账号与访问范围

这份说明记录本地实现与上线前的必做检查。首页、博客列表和博客正文公开。作品、资料、软件推荐、资源中心及其他内容栏目要求读者登录。资源中心书籍可由作者逐本选择“仅 VIP 可阅读”；未勾选的书仍对所有已登录读者开放。VIP 目前由作者手动开通，没有站内支付、自动续费或社区发言入口。读者账号不能进入作者台。本段所述书籍权限尚未部署到线上。

浏览器中的遮挡只是交互提示。真正的权限检查在服务器：内容列表、正文、书籍小节、相关图片与附件在每次请求时核验登录状态；`public=1`、缓存验证和直接复制接口地址都不能绕开它。公开博客中引用的同一张图片仍属于公开图片。读者管理入口为 `#/admin`，作者台内可直接跳转；操作接口仅认现有作者身份，入口地址本身并非秘密。现有 Payload 管理台 `/manage/` 仍是另一套作者工具。

读者注册时必须填写昵称、邮箱、手机号和密码。手机号仅作为账号联系资料，不发短信，也不能用未经验证的号码找回账号；邮箱验证通过后才能登录。读者可在“我的账号”修改昵称和手机号、退出、通过邮件找回密码。密码重置会撤销该账号此前的全部登录会话，要求所有设备用新密码重新登录；短密码会显示密码规则，失效链接会显示链接错误。每个读者账号在创建时分配独立的 UID，从 `0001` 起按创建顺序递增；补入旧账号时按注册时间和内部 ID 排序。UID 不因重新登录或改昵称、手机号而变化，也不会因删除高位账号而重用。读者登录后在页脚和账号页看见自己的 UID；作者后台同时显示 UID，仍以不可猜测的内部 ID 处理权限。作者使用同一个登录表单，凭现有作者账号进入作者台；作者台有“后台管理”入口。读者管理页展示账号总数、可登录、待验证、已停用四项统计；可按 UID、邮箱、手机号或昵称搜索，按状态筛选并翻页。点击账号可查看详情，停用、恢复或撤销登录前有二次确认；最近 20 条已完成操作可在“操作记录”查看，私有审计文件保留原始记录。读者自己的会话接口可返回自己的手机号以便更正，不向匿名访客返回。注册、登录与邮件请求有频率限制。后台单独路径不等于独立服务器或独立域名。

后台“会员权限”支持由作者手动开通、续期或撤销 VIP。首次开通从操作时刻到下个月同日同一时刻；若目标月份没有该日，则落在当月最后一天。有效期内再次开通，从原到期时刻延长一个自然月。到期时，服务器在读取账号状态时立即判为普通读者；不依赖定时任务，也不自动扣费。登录者可见 VIP 标识，后台可见到期时间和剩余时间；相关操作写入审计记录。本地新增的逐书开关会在服务端同时限制正文、章节、正文插图和附件；普通读者仍可看书名、摘要与封面。提示中的“开通 VIP”跳转到作者提供的 QQ 联系链接，不执行支付或自动开通。上线前须备份并运行 `node scripts/migrate-vip-books.mjs <private-payload-directory>`，再验证普通读者、VIP 和作者三种账号；该脚本是增量迁移，现有书籍默认保持公开给登录读者。

成功登录读者或作者时，私有数据库 `login_events` 会逐次记录账号编号、邮箱、UTC 时间、网站观察到的来源 IP、直连端地址、地址来源（直连或本机 Nginx）及浏览器 User-Agent。读者管理列表显示最近一次登录 IP 和时间；账号详情显示最近 20 次，底层表保留完整历史。读者接口不返回这些字段；管理员接口每次都检查作者身份。迁移脚本在添加审计表前生成数据库备份。IP 是网络出口地址，VPN、代理、运营商共享地址会影响它与实际使用者的对应关系，不能将 IP 单独当作实名身份。

当前 Nginx 配置把 `$remote_addr` 放进 `X-Real-IP`；Node 只在直连端是本机回环地址时信任该字段，直连请求携带的 `X-Real-IP`/`X-Forwarded-For` 均不能覆盖套接字地址。若将来为 HTML/API 接入 CDN、负载均衡或另一层代理，必须重新核对可信代理链和真实客户端 IP，再开放登录。现有 EdgeOne 仅用于静态资源，不应据此推断动态登录请求已处于 CDN 后面。

## 本地验收

`pnpm build`、`pnpm test`。`node scripts/reader-preview.mjs` 会把当前本地内容数据库复制到 `.local` 中的隔离目录，在 `http://127.0.0.1:4194/` 演示；默认不连接 SMTP，注册明确返回服务未就绪。只有显式设置 `READER_PREVIEW_SMTP=1` 才会读取本机私有邮件配置，表单提交时可能发送真实邮件。预览不修改原数据库或线上网站。用未登录浏览器核对博客正文可读、其他栏目返回登录提示；再直接请求 `/api/content?view=list&kind=works&public=1`，应为 401。

2026-09-25 使用当日线上备份的**本地副本**完成了账号和 VIP 迁移演练：两项迁移首次成功、第二次均无更改；SQLite 完整性正常，原有文章 2、栏目条目 10、公告 3、媒体 172、资料记录 1 的核心字段逐项相等，现有书籍没有被误设为 VIP 专属。本地服务在该副本上验证匿名读者只能访问博客，直接请求受保护内容和读者后台分别返回 401/403，缺少 SMTP 时注册返回 503。未登录请求受保护的详情会先被拒绝，不再触发整份公开内容快照的读取。本机 SMTP 加密连接与认证成功，但用户暂未提供自己的 QQ/网易测试邮箱，**真实投递和找回密码邮件收信仍未验收**。这些结果只证明本地副本，不代表线上功能已启用。

## 正式启用前

1. 阿里云邮件推送 DirectMail 已在本机接通，`mail.sansphase.com` 的 SPF、DKIM、DMARC、MX 已解析且通过阿里云验证，`no-reply@mail.sansphase.com` 发件地址状态正常；本机 SMTP 加密连接及认证通过。**真实 QQ／网易邮箱的投递、验证链接和找回密码尚未验收，线上尚未配置 SMTP，也未上线此功能。** 上线前在服务器私有 `/etc/sansphase/payload.json` 添加 `smtp`：`host`、`port`、`user`、`password`、`from`，可选 `name`。缺少任一必填字段时，网页保持“注册暂未开放”。不要把密码写进源码、聊天记录或公开仓库。没有可靠邮件投递时，不要开放注册。
2. 按既有流程备份数据库、上传文件和配置，并在**隔离副本**上先运行 `node scripts/migrate-reader-accounts.mjs <private-payload-directory>`，演练新版本启动与回退。该迁移会先备份，再补 UID、会员时间字段和登录审计表；旧读者 UID 会按注册时间确定。正式迁移也必须在已验证备份后执行；日常启动保持 `push:false`。
3. 在隔离版本核对匿名、已登录、停用账号、作者四种身份的页面、内容接口和图片/附件；检查 Nginx 的登录限流面对真实客户端 IP 是否有效。发布与回滚按 `docs/RELEASE-PROCESS.md` 执行。数据库结构迁移后，单独回退代码不能自动撤销表结构。
4. 从外网用不同网络分别登录测试账号，核对后台的 IP 与 Nginx 访问日志、UTC 时间一致；不能仅用本机演示地址验收“准确 IP”。核对服务器实际 `logrotate` 或等效策略，确保相关网络日志不少于六个月，并验证日志、审计数据库及备份的访问权限、异地备份和恢复。**当前代码没有自动删除旧登录记录，现有备份也无保留期限策略；上线前需要确定必要的保存期限、法定留存及调查保全例外，配置到日志与备份，并完成正式、易访问的隐私告知。仅有 ICP 备案或这段登录页提示不能证明全部合规。**

收到依法提出的协查请求时，先保留原始数据库与同期 Nginx 日志的只读副本及文件哈希，记录提取时间、范围和经办人，再按合法程序提供与请求范围相符的资料；不要直接修改原始记录或把完整用户库公开发送。已有会话在此功能上线前的登录 IP 无法由新审计表倒填。

后续社区开放时另加版主管辖范围和发言权限。VIP 将来必须由服务端记录权益并检查，不能只在前端隐藏内容。

## 低成本邮件接入候选

优先考察国内方案。当前官方资料显示，[阿里邮箱企业邮箱免费版](https://help.aliyun.com/zh/document_detail/446177.html)允许个人实名认证账号申请，支持自有主域名或子域名，已实名认证可自动免费延期，企业外部发信上限为每天 2,000 封。它的 [SMTP 地址](https://help.aliyun.com/zh/document_detail/36576.html)为 `smtp.qiye.aliyun.com:465`，但新邮箱默认禁止第三方客户端，须在管理后台为专用发件账号开放 SMTP，并使用独立的[第三方客户端安全密码](https://help.aliyun.com/zh/document_detail/606337.html)。这是面向日常通信的邮箱服务；网站自动验证信是否稳定、是否触发反垃圾限流，应在正式使用前用真实收件箱验证，不把名义上的日额度当作可保证的实际投递能力。

[阿里云邮件推送 DirectMail](https://help.aliyun.com/zh/direct-mail/billing-methods)是专门发送事务邮件的服务，也支持 SMTP，适合注册、找回密码等用途。其每个主账号仅有**累计** 2,000 封免费额度、免费期间每天最多 200 封；用完后官方当前按量价格为每 1,000 封 2 元，可能产生费用。若选择它，先按控制台指引验证专用发件域名、创建发件地址和 SMTP 密码，再把控制台给出的设置填入私有配置；不要猜 DNS 记录值。[SMTP 服务地址](https://help.aliyun.com/zh/direct-mail/smtp-endpoints)随所选地域而异。

[腾讯云邮件推送](https://cloud.tencent.com/document/product/1288/47930)给每个账号累计 1,000 封免费邮件，之后按量收费。不过[腾讯云产品动态](https://cloud.tencent.com/document/product/1288/54785)说明，2026 年 3 月起新开通的个人实名认证账号不再支持 SMTP，需接 API 或改用企业认证，因此不能直接套用本站当前的 SMTP 配置。[Resend](https://resend.com/pricing)目前有按月更新的免费额度，可作为备用选项；若选择它，要另测对 QQ、网易邮箱的投递。任何供应商的价格、申请资格和限额开通前都应再次核对。

无论发送服务是哪一家，`from` 应使用已验证的自有域名地址；按控制台**当时提供的**记录添加 SPF/DKIM，避免覆盖网站现有 DNS。接收方使用 QQ、Gmail 或网易邮箱，不要求发送服务也由对应公司提供。

阿里邮箱免费版的候选落地步骤：在[官方申请页](https://common-buy.aliyun.com/?commodityCode=alimail&specCode=lx_18482)以实名认证账号确认显示零元，再选择尚未用于邮箱的域名或子域名（例如 `mail.sansphase.com`）；按照邮箱控制台实际给出的 DNS 记录配置，并在申请后 7 天内完成解析。创建仅用于站点通知的邮箱账号，允许该账号访问 SMTP，生成独立的第三方客户端安全密码。接着在隔离环境填写私有 SMTP 配置并运行下方的连接与真实投递测试。若购买页报价不是零元、账号不满足条件，或 QQ/网易/Gmail 投递不稳定，就停止此方案，改评估 DirectMail。不要在未核对记录时使用“一键添加”覆盖已有的主域邮箱解析。

私有配置字段示意如下，尖括号中的内容不能原样用于生产：

```json
"smtp": {
  "host": "<所选服务商的 SMTP 主机名>",
  "port": 465,
  "user": "<专用发件账号或 SMTP 用户名>",
  "password": "<从服务商控制台创建的专用密钥>",
  "from": "notice@<已验证的发件域名>",
  "name": "SANSPHASE"
}
```

配置后，在隔离环境先运行 `node scripts/check-reader-email.mjs` 验证连接和身份，再显式运行 `node scripts/check-reader-email.mjs --send-to=你的测试邮箱`。第二条命令才会发送一封测试邮件。服务商接受邮件不等于用户已收到；必须人工检查收件箱和垃圾邮件箱，再跑注册、验证和找回密码流程。站点默认拒绝明文 SMTP 降级：465 使用直接 TLS，其余端口要求 STARTTLS。

本机代理 DNS 曾将邮件主机解析到不可达地址；本机私有配置暂用可选 `connectAddress` 指向已验证的阿里云地址，同时用 `host` 做 TLS 证书主机名校验。不要把临时 IP 写入网站源码，正式服务器应先独立检查 DNS 和 SMTP 连通性，再决定是否需要该选项。

收件邮箱不绑定某一家平台。QQ（`qq.com`）、Google Gmail（`gmail.com`）和网易（`163.com`、`126.com`、`yeah.net`）都走同一套邮箱验证流程；自动化测试覆盖这些地址的注册、生成验证信、验证和登录。真正开放注册前，仍须使用真实测试邮箱分别检查三家服务商的实际收件时间、垃圾邮件分类、验证链接打开以及密码找回。代码接受地址并不等于邮件必然送达。
