# 稳定性与性能诊断

项目所有者于 2026-10-15 确认先做本地稳定性与卡顿排查，保留现有 UI/UX；于 2026-10-16 授权交付检查通过后上线。此次不调整发帖审核、用户权限和账号数据，也不公开推送。文档描述候选版能力；实际是否启用、运行版本与验收结果以服务状态及私有发布回执为准。

## 选型与边界

性能测量采用 [GoogleChrome/web-vitals](https://github.com/GoogleChrome/web-vitals) **6.2.3** 的普通入口，Apache-2.0，无新增运行时依赖。版本、依赖完整性记录在 `pnpm-lock.yaml`。已核对上游 CHANGELOG：此版本修复 INP 清理造成的内存泄漏；不采用预发布版本或自写 Web Vitals 测量算法。上游原许可由现有构建流程保留在 `dist/assets/licenses/`。

暂不引入 Sentry 或另一个监控服务，避免额外服务、账号、存储和前端体积成本。本站仅增加事件脱敏、批量传送和有界接收的薄适配。异常监听复用浏览器 `error` / `unhandledrejection`；长任务复用 `PerformanceObserver`，不自行模拟响应时间，不改写全局 `fetch` 或现有路由。

本轮是诊断基础，不代表网站已经加速，也不能用本机测试代替真实用户数据。页面连 HTML 都无法连接时，浏览器脚本尚未运行，这种网络/TLS 故障仍需独立可用性监测与服务端日志。

## 本地启动

先使用项目要求的 Node 24.21.x 和锁定的 pnpm 版本构建：

```powershell
pnpm build
pnpm preview:diagnostics
```

默认访问 `http://127.0.0.1:4252/#/community/home`，也可打开同一预览下的 `/#/notes` 和 `/blog/reading-preview`。端口可用 `PORT` 修改。预览复用既有合成账号和临时数据库，不读取私有配置，也不连接线上数据库。停止进程后，预览删除其临时社区数据库。

本机报告：`http://127.0.0.1:4252/api/diagnostics/report`。它提供已接收的匿名事件和统计摘要，便于开发核验；本轮不增加网站内的管理面板或悬浮工具。诊断事件只保存在内存，最多 5,000 条，最多保留 24 小时；进程重启后清空，不产生备份、业务表或持续增长的日志文件。

## 记录什么

| 数据 | 用途 | 限制 |
| --- | --- | --- |
| LCP、FCP、TTFB | 内容出现、首屏和服务器响应耗时 | 由 web-vitals 测量；不发送原始 performance entries |
| INP | 点击等交互到画面更新的响应时间 | 没有有效交互时可能没有数值，不补造 0 |
| CLS | 页面布局跳动 | 不是毫秒，不与耗时混用 |
| 长任务耗时 | 识别主线程被持续占用 | 只记录时长和固定页面类型，不采集任务归因内容 |
| 脚本、Promise、资源异常 | 判断哪个页面发生技术故障 | 只记录固定异常类别和可选行号，不记录原始异常文本 |

脚本与样式资源过滤器只识别同源静态文件，以及当前文档 `data-static-base` 指定的、经过批准的 `static.sansphase.com/assets/site/<当前摘要>/` 发布包。其他域名和旧发布包不采集；资源地址只用于浏览器内过滤，不进入事件。

页面归类只用固定值，例如 `note`、`community-profile`、`community-shop`，不记录文章 slug、用户 UID、帖子编号、查询参数、hash 或邀请 token。服务端自己添加接收时间，不依赖用户设备时钟。

不记录正文、聊天、表单输入、邮箱、账号标识、IP、User-Agent、Cookie、storage、referrer、截图、DOM selector、错误 message/stack、完整 URL 和请求响应内容。不使用 web-vitals attribution 入口、会话回放或外部上报。尊重浏览器 DNT/GPC 偏好。

## 不干扰现有网站

- 默认关闭。正式启动仅在明确设置 `SITE_DIAGNOSTICS=1` 时创建生产适配，`0` 或未设置均关闭；其他值拒绝启动，避免误配。仅抽中样本的页面加载诊断 bundle；未抽中的页面没有诊断请求。
- 页面先渲染，空闲时再动态加载；不添加、移动或改写可见 DOM，不更改 CSS、主题、滚动位置、焦点和按钮行为。
- 有限队列、有限发送次数、小批量上报；发送失败不重试，不弹提示，不阻断业务。停止时清理本模块的监听器、定时器与长任务观察器。
- 本地预览的三个端点仍只供 `127.0.0.1` 使用，拒绝生产环境。本地适配与正式适配分别检查实际 socket、Host、Origin 和请求来源，不相信转发头。业务路径仍经过原来的社区入口白名单。
- POST 限制为 8 KiB、每批 20 条，拒绝未知字段、非法数值和混入内容的事件；服务端有请求速率、在途读取和读取时间上限。

## 验证与后续

回归覆盖默认关闭、显式启用、隐私字段拒绝、事件上限、发送失败、重复挂载、清理、主机/来源校验、过大/慢请求、保留期以及正常 HTTP 路由保持原行为。浏览器验收使用新的隔离配置目录，不操作用户正在使用的浏览器。

Web Vitals 通常在用户交互、页面转为后台或离开时定稿；不是每次打开报告都立即得到五个数。长任务也依赖浏览器支持，后台页和不支持的浏览器不能用“没有记录”断言“没有卡顿”。整页指标不会自动变成每次 hash 跳转的独立指标，不能把路由归类当成完整的 SPA 导航计时。

## 正式环境与报告边界

`scripts/start.mjs` 与 `scripts/start-community.mjs` 复用同一正式适配，只接受 `https://www.sansphase.com` 和 `https://community.sansphase.com`。服务仍监听回环地址，位于现有 HTTPS 代理之后。每次文档响应独立随机抽取约 10%，不设置用户标识、Cookie 或 storage；这不是“10% 的用户”或完整访问量统计。DNT/GPC 请求头禁止下发启用标志，浏览器偏好也在加载 bundle 前和初始化时再次检查。

公网仅允许 `POST /api/diagnostics/events`：要求真实回环代理连接、准确的本站 Host 与 HTTPS Origin，不需要登录，不续期会话，不签发社区入口票据。报告和配置的 GET 要求 `127.0.0.1:应用端口` Host、回环连接、无 Origin、无浏览器 Sec-Fetch 头、无转发头。现有 Nginx 保留公网 Host 并添加转发头，所以不能经公网读取报告；也不增加后台可见入口。维护人员先通过原有 SSH 身份验证，再在对应服务器执行：

```sh
curl --fail --silent http://127.0.0.1:4176/api/diagnostics/report
```

接收最多每分钟 120 批，每批最多 20 条、8 KiB，最多 8 个在途请求且读取限时 3 秒；本机报告最多每分钟 30 次。两个站点分别保存最多 5,000 条事件，最长 24 小时；只用有界内存，进程重启立即清空，**不提供跨重启历史趋势**。无新数据库、迁移、磁盘日志或备份增长；如以后需要长期趋势，应另行确定聚合存储和保留规则。

诊断事件不包含账号、正文、IP、完整链接或原始错误内容，与网站既有登录审计及 Nginx 运维日志是不同数据。匿名客户端可伪造符合结构的测量，因此这些样本只用于技术排查，不能作为计费、处罚或安全审计依据。全局预算达到上限时会丢弃样本，不阻断任何业务。

覆盖加载 `app.mjs` 的主站与社区页面；独立管理台、独立茶室壳层未新增采集，不能宣称全站每一页都已完整监控。性能库空闲加载，过早离开或不支持相关 API 的浏览器可能没有完整指标；捕获不到已经发生在加载之前的所有异常，也不包含已被业务处理的请求错误。关闭环境开关并重启可停用采集，回退代码不需要回退用户数据。
