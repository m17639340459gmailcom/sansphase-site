# 社区管理台：保留原界面的本地预览

## 当前确认的方向

2026-10-12 用户看过独立 React-admin 社区控制台后，指出它偏离原来的 UI，并明确选择“按原社区管理台恢复”：侧栏、字体、背景、卡片和操作位置尽量保留，只在原界面补能力。

当前以原来的 `/#/community/manage` 为唯一社区管理工作台。主站作者后台中已认可的用户、备注、维护和操作记录模块保持原状；不将主站的通用管理界面套到社区。此前实验方案保存在 Git 提交 `4434389`，它不代表视觉验收通过。

## 实施边界

- 直接复用 `community-management.ts/css`、`community-pages.ts`、`community-ui.ts`、社区主题与顶部账号区域。暖色纸面/深蓝背景、原字体、角色栏、统计卡片、按钮及菜单顺序继续由这些模块负责。
- 原有内容审核、资料审核、举报、精选推荐、横幅、兑换发货、商品上架及管理成员保留在同一个工作台，不再要求在两个控制台来回切换。已发布帖子在原帖操作；旧帖子管理地址只保留兼容访问。
- 原帖详情、编辑、置顶、精选继续使用原位置；审核仍支持原单条和批量流程。实验新版中的就地详情、表格筛选分页暂不迁入；如确有需要，后续按原卡片结构做局部补充。
- 移除仅供未通过视觉验收的社区 React-admin 外壳使用的页面、身份/数据适配与专属测试，避免留下两套状态管理。React-admin 仍用于已认可的主站后台。
- 先前分享的 `/community-console/#/queue|content|reports|orders` 等地址仅作兼容跳转，复用原路由白名单，返回相应旧栏目。入口不请求身份、不授权、不修改数据、不加载另一套后台框架。
- 兼容入口只带回单一合法的 `communityTheme=light|dark`、`lang=zh|en` 参数；私有筛选、任意返回地址及非法路径不透传。原主题/语言控制器仍按原行为工作，保留参数不代表改变其默认值。
- 不修改服务器 API、管理权限、奖励规则或处罚规则。原删除面板仍按既有权限提供“按违规处理”选项，不能把实验版“不追加处罚”的固定策略误称为原台行为。
- 原接口最多返回最近 100 篇可管理帖子，不宣称已实现全站检索。

## 菜单精简（2026-10-12）

用户确认移除左侧独立的“帖子管理”入口。内容审核继续集中处理待审和举报；已发布帖子的编辑、删除、置顶和精选仍在原帖中按原权限操作。只精简重复菜单，不删除已发布帖子、后端权限或接口；旧的帖子管理书签仍可打开，避免已有链接失效。

## 本地预览

运行 `pnpm preview:community-console`，默认端口 4250，可通过 `COMMUNITY_CONSOLE_PORT` 指定其他本机端口。

- 身份选择：`http://127.0.0.1:4250/api/community/preview-identity?theme=light`
- 原管理台：`http://127.0.0.1:4250/?communityTheme=light#/community/manage/queue`

选择作者或管理层级后直接进入原管理台；普通读者没有管理权限。同一浏览器标签页共享演示身份，切换后刷新其他标签页。

预览从当前正式源码单独构建，全部内容、账号、订单为临时合成数据。显式 `managementDemo` 仅为合成管理账号准备已同意公约的状态；普通读者及其他预览默认行为保持不变。仅绑定回环地址并校验 Host，不连接生产数据或读取私有配置。

旧 `/community-console/` 的兼容入口保留在这个本地服务中；没有加入正式服务路由或正式发布流程。原 4249 预览与根 `dist` 不被覆盖。

恢复原界面后补齐了预览原本漏跑的等级、徽章、管理身份和 VIP 头像框派生素材步骤，直接调用正式构建的三个现有生成器。它修复的是本地素材 404，不是修改原图、用户资格或生产部署。

## 保留封面、明亮昵称纯黑（2026-10-12，当前本地修订）

用户否决衬底后进一步明确：“明亮模式 改成黑色即可 无需描边”。最终按这一要求执行：移除衬底及为它新增的定位/裁切/隔离样式，也不保留中间尝试的描边、简介阴影或按钮填色。

相对本轮开始前的 `a6a9f47`，`community.css` 完全一致；生产代码仅在 `community-layout/appearance.css` 增加个人主页大昵称的明亮主题规则：纯黑文字、纯黑填充、无背景渐变、无阴影、无流光动画。明亮主题下该处已有彩色昵称也显示黑色；深色主题继续原来的配色和昵称特效。封面、头像、UID、简介、按钮、昵称旁图标、尺寸和位置保留原来行为，没有增加 JS、图片取色、依赖或 API。
