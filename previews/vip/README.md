# 本地个人中心与 VIP 演示

此目录为维护源码，但**不在生产发布清单，也不在网站构建入口**。不得复制到生产服务器挂载，也不得将模拟支付接口接到正式账号。真实付款接入需另行完成商户能力核实、服务端验签和对账；本演示没有收款二维码。

在项目根目录运行：

```powershell
pnpm build
node --test previews/vip/orders.test.ts
node previews/vip/server.ts
```

打开 http://127.0.0.1:4210/ 。三个演示账号为普通读者、临近到期 VIP、已到期会员。开通或续期时选择 QQ/微信，填写测试联系方式，同意规则并创建订单。用明确标注的模拟按钮测试成功、失败、取消。关闭充值弹窗不会取消待支付订单。个人中心只显示“我的订单”按钮，点击打开独立订单窗口，每页 5 笔，点单条可展开明细、继续支付；打开前只读取总数，不加载全部订单。

个人资料卡、会员摘要复用正式 TS 模块；头像及资料编辑在本演示中不提供操作，原网站的编辑和审核功能保持原样。返回博客指向另一个本地示例页面（先运行 `node scripts/catalog-fixture-preview.mjs`，端口 4177）。

测试数据仅保存于 `.local/vip-batch-preview/demo.db`，重启保留，不读取既有账号配置或线上数据库。订单和会员在同一 SQLite 事务中更新，已成功订单重复确认不增加时长，失败/取消订单不能再变成成功；订单按演示用户隔离。此隔离是测试逻辑，不是正式用户登录授权方案。

业务逻辑在 orders.ts，充值/账号交互在 client.ts，订单明细与分页复用 order-view.ts，作者端在 admin-client.ts；公共演示样式在 preview.css，订单样式在 order-view.css，HTTP 服务在 server.ts。价格由服务端固定为 20000 分，一次增加一个自然月；复用现有会员月计算函数（UTC 日历，短月钳制）。正式支付前仍需核对月末北京时间边界，与既有会员保持一致或明确迁移规则，不能悄悄更改。

正式发布包通过 scripts/publication-files.mjs 的明确清单产生；previews/ 未列入。模拟支付按钮、联系人资料和数据库不会进入 dist。订单采用服务端分页，不再截断为最近 100 笔；该实现仍只服务于本地演示，不代表正式订单接口已经上线。

## 作者查看订单

打开 http://127.0.0.1:4210/admin 或点击页面顶部的“作者后台预览”。沿用现有后台外壳，只提供本次订单管理演示，其他正式管理菜单不挂载。作者可查看所有演示用户的昵称、UID、订单号、金额、联系账号和状态，按状态筛选；每页 10 笔，“详情”弹窗提供支付时间及本次续期至时间。用户付款后，作者重新进入或点“刷新订单”读取最新数据。

作者预览为只读，使用与读者预览不同的本地能力标记；读者标记不能直接请求作者订单接口。/admin 本地页面仍可直接打开取得演示能力，这不是正式管理员鉴权；不得将此服务发布到公网。真实接入必须复用正式作者认证，并将订单归属绑定服务端已登录用户，不能信任演示用的账号请求头。
